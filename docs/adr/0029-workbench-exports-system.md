# 0029：审核提速、工作台与筛选、导出记录与系统信息

- 状态：已采纳
- 日期：2026-11-12

## 背景

设计说明第十一节 v2 第 5、6、7 项。第 4 项（ADR 0028）有了字段的红黄绿，接下来要让审核员
一份接一份地审，打开系统就知道今天要做什么，导出过的文件找得回来，出问题时一眼看出是哪个服务。

## 决定

### 审核提速（第 5 项）

1. **上一份 / 下一份**：`GET /documents/{id}/neighbors`，按文档列表的顺序（上传时间倒序），
   只算待审核（`done`）的。审核页标题左边两个按钮；点"完成审核"后自动打开下一份。
2. **点原图选字段**：鼠标移到原图上，对应字段（包括商品明细里平时不画框的格子）的框亮出来；
   点一下就选中右边的字段。一个点落在几个框里时选最小的那个。
3. **确认没问题的**：一次确认这一页"原文一致 + 规则通过"、还没人确认过的字段，每个记一条确认记录。
   和"全部确认"（确认标黄等你确认的）分开，两者的意思不一样。
4. **窄屏**：宽度小于 992 像素时左边菜单收起（顶栏左边的按钮打开）；审核页原图在上、字段在下。

### 工作台与筛选（第 6 项）

5. **处理进度**：`documents` 加 `stage`（"识别文字""抽取第 2 / 3 页""保存结果"）和 `progress`（0～100），
   worker 每开始一步写一次（单独的短事务，马上看得到）；处理完清空，记 `processed_at`。
   完成审核记 `reviewed_at`。流水线 `Pipeline.run` 多一个 `progress` 回调，命令行不传就不报告。
6. **工作台** `GET /dashboard`，也是登录后的首页：各状态多少份、待确认字段总数、今天处理完 / 审核完多少份、
   最近 7 天每页平均用时；"需要先处理"（失败的 + 待确认字段最多的待审核文档）；处理队列（带进度）。
   "今天"按这台电脑的时区算。
7. **列表筛选** `GET /documents?status=&template=&date_from=&date_to=&q=&pending=`：状态可多选、
   模板、上传日期（含两头）、文件名（不分大小写，% 和 _ 当普通字符）、只看还有待确认字段的。
   条件放在网址里，工作台的统计卡点进来就是筛好的列表。

### 导出记录与系统信息（第 7 项）

8. **导出记录**：新表 `exports`（谁、什么时候、格式、文档 id 和文件名、大小、文件位置）。
   每次导出的文件存进对象存储 `exports/<id>.xlsx|zip`，`GET /exports` 列出，
   `GET /exports/{id}/file` 重新下载（拿到的是**当时**的内容），重新下载记审计日志 `export:download`。
   存文件失败不影响这次导出，只是记录上标"不能重新下载"。导出仍然不改变文档状态（设计说明的取舍不变）。
9. **系统信息** `GET /system`（只读，登录了就能看）：版本、模式、模型服务地址、正在用的模型和上下文长度
   （问 llama-server 的 `/props`，连不上就空着）、models/ 里的模型文件、OCR 引擎和版本、模板、
   数据量（文档、页、字段、审核记录、原始文件和导出文件的大小），以及和 `jacara doctor` 同一套的服务检查。
   不显示任何密码。"模型管理（只读）"并入这一页。

## 后果

- 新迁移 `b41c2e7d9a15`：`documents` 加 4 列，新建 `exports`。已经处理完的文档 `processed_at` 用上传时间补上。
- 导出的文件会占对象存储空间；清理放到 v3 的"保留期限"。
- 文档状态仍然是 5 个（没有"审核中""已导出"）。
