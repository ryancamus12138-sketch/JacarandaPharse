# 0032：个人资料、按字段内容找、先跳过、备注（v3 第 1 批）

- 状态：已采纳
- 日期：2026-11-12

## 背景

v3 第 1 批是几件让日常使用更顺手的小事：

- 右上角的名字、左边菜单顶上的头像和昵称要能点进"个人资料"，自己改昵称、换头像、改密码；
- 按单据上的内容找文档（发票号码、商家名），不只按文件名；
- 审核时拿不准的先跳过，过后再回来；
- 在文档或某个字段上给同事留话（"这张要问财务"）。

## 决定

### 个人资料

- 团队模式：昵称就是 `users.display_name`（本人改、管理员也能改），不另存一份。
- 个人模式没有用户账号：昵称和头像记在新表 `profiles` 里 `PERSONAL_OWNER.user_id` 那一行。
  `profiles.user_id` 不连 `users` 表，就是为了个人模式也能用。
- 头像：PNG / JPG / WEBP，5 MB 以内；后端转正、裁成正方形、缩到 256 × 256、重新存成 PNG
  （不带原图的 EXIF，比如拍摄地点），放在对象存储 `avatars/<user_id>.png`。
  `profiles.avatar_at` 记最后一次换的时间，前端拿它当版本号，换了就重新取。
- `/auth/me` 多返回 `shown_name`（昵称 → 用户名 → "本机用户"）和 `avatar_at`，顶栏和菜单不用再查一次。
- 接口：`GET/PATCH /auth/profile`，`GET/PUT/DELETE /auth/profile/avatar`。审计记 `profile:update`、
  `profile:avatar`、`profile:avatar_remove`，不记昵称内容以外的东西。

### 按字段内容找

文档列表加 `value_q`（和可选的 `field`，界面上可以选"在哪个字段里找"，选了模板就列这个模板的字段）：当前这一轮任意字段的值里包含这些字（不分大小写）。
模型抽的原值和人改过的值都算（改过几次的，任何一次的值都能找到）。`%`、`_` 当普通字符。

### 先跳过

- `documents` 加 `skipped_at`、`skip_reason`、`skipped_by`。只有待审核（done）的能跳过，要"完成审核"权限。
- 跳过的不算进"上一份 / 下一份"，也不在工作台"需要先处理"里；工作台显示先跳过了几份；列表用 `skipped=true/false` 筛。
- 取消跳过、完成审核、重新处理都会清掉跳过。

### 备注

- 新表 `comments`：挂在整份文档（`field_name` 为空）或某一页的某个字段上（`page` + 字段 ID，表格的一格是 `items.2.amount`）。
  多页文档里不同页可能有同名字段，所以字段备注必须带页码。
- 审核页上，有没解决备注的字段和表格格子旁边显示一个小图标。
- 能看这份文档的人都能看、能写、能标已解决；只有写的人或管理员能删。
- 审计日志记 `comment:create / resolve / reopen / delete` 和备注 id，不记备注内容。
- 文档列表的每一项多一个 `open_comments`（没解决的备注几条）。

## 没做的

- 不按字段给备注发通知（离线、单机，没有消息推送）。
- 个人资料不能改用户名（登录名），要改找管理员新建账号。
