# 0020 多个文档导出：每份一个 Excel，打包成 zip

- 状态：已采纳
- 日期：2026-11-11

## 背景

最初的多文档导出是"汇总到一个 Excel，一行一张单据"。实际用的时候，更常见的需求是
一张单据对应一个文件：按单据归档、单独发给别人、和原图放在一起。

## 决策

**多个文档默认每份一个 Excel，打包成 zip。** 浏览器一次只能下载一个文件，没有"下载文件夹"，
所以打包；在 Mac 和 Windows 上双击 zip 就是一个文件夹。

- 新接口 `GET /api/v1/documents/export.zip?ids=…`，`DocumentService.export_zip()`；
- zip 里的文件名跟原文件同名（`receipt.jpg` → `receipt.xlsx`），重名的加 ` (2)`、` (3)`，按用户选的顺序；
- 每个 Excel 和单个导出的完全一样（汇总表 + 明细，改过的标蓝、有批注）。

**汇总导出保留**，放在按钮旁边的下拉里：对账时一行一张单据很方便。

**两种导出共用检查和审计。** 原来 `export()` 里的检查（权限、数量上限 100、找不到、没处理完）
拆成 `_exportable()`，生成 Excel 拆成 `_workbook()`，审计拆成 `_record_export()`，
审计日志的 detail 里多记一个 `format`（`xlsx` 或 `zip`）。

**前端**：只选一个文档时是普通的"导出 Excel"；选多个时主按钮是 zip，小箭头里是汇总。

## 后果

- 每份 Excel 都在内存里生成再打包。100 份（上限）也只有几 MB，本机可以接受。
- zip 里没有放原图。需要的话以后可以加一个选项，把原图一起放进去。

## 放弃的方案

- **一次触发多个下载**（每份一个 .xlsx 分别下载）：浏览器会拦截"一个网页连续下载很多文件"，
  要用户逐个允许；下载文件夹里也会散落很多文件。
