# 0008 PDF 输入：文字层优先，扫描件 OCR

- 状态：已采纳
- 日期：2026-11-03

## 背景

很多发票是 PDF。电脑生成的 PDF 自带文字和坐标，用 OCR 反而又慢又可能读错；
扫描件或拍照转的 PDF 只有图片，必须 OCR。

## 决策

**装载器（`plugins/ocr/loader.py`）：** `load_pages(文件, OCR 引擎) -> list[OcrPage]`，一页一个。
后面的抽取、对齐、校验、导出不变。

- 图片：直接 OCR。
- PDF 每一页：先用 pdfplumber 读文字层（`keep_blank_chars=True`，同一行挨得近的词合成一段）；
  文字少于 10 个字就当作扫描件，用 pypdfium2 渲染成图片后 OCR。
- 坐标统一为"PDF 按 3 倍渲染后的像素"（约 216 DPI），文字层和扫描件一致，方便审核页面高亮。
- 文字层的置信度为 1.0；来源记录为 `pdfplumber 版本` 和"PDF 文字层"。
- 多页 PDF 每页单独抽取，Excel 里每页一行。

**对齐器补充：** 日期支持英文月份（August 3, 2014、3 Aug 2014 等），比较时忽略大小写，
并去掉逗号、句号前多余的空格（PDF 常见 "August 3 , 2014"）。

**授权：** pdfplumber（MIT）、pypdfium2（Apache 2.0 / BSD）。不用 PyMuPDF（AGPL）。

## 第一次试用

- AWS 电子发票、OYO 酒店收据：走文字层，约 30～40 毫秒；4 个字段全部有出处。
- 收据图片转成的扫描件 PDF：自动 OCR，14 个字段结果与原图一致。

## 局限与后续

- 多页单据（总额在第 2 页）目前按页分别抽取，以后需要整份文档一起抽取。
- 商家名该填品牌还是公司全称是业务规则，交给模板功能按用户需要配置。
- 表格（商品明细）仍未抽取，等表格识别接入。
