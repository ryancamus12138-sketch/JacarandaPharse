# 0015 导出 API

- 状态：已采纳
- 日期：2026-11-08

## 背景

Excel 导出（ADR 0007）只能在命令行里用，导出的是模型原值。有了人工审核（ADR 0014）之后，
用户要的是审核之后的值，并且导出的文件本身也要能追溯：哪些格子被人改过、原来是什么、为什么改。

## 决策

**导出器继续只认 `DocumentReport`（项目规则 7：插件不碰数据库）。** 新增 `pipeline/load.py`，
把数据库里的文档、抽取、字段、审核记录拼回 `DocumentReport`；`store.py` 是存，`load.py` 是取。
出处在数据库里只存了合并后的框和最低置信度，还原成一个"文字块"，`bbox` 和 `confidence` 与原来一致。

**`DocumentReport` 新增 `reviews`（字段名 → 最新一次审核），默认为空。** 只加字段，
命令行导出和旧代码不受影响（项目规则 9）。

**Excel 里怎么显示审核：**

| 情况 | 格子的值 | 颜色 | 批注 |
| --- | --- | --- | --- |
| 人工修改过 | 审核之后的值 | 蓝 | 原值 → 新值、原因、时间、出处 |
| 人工确认过 | 原值 | 无 | 人工确认、时间 |
| 需要确认、还没人看 | 原值 | 黄（找不到出处为红） | 原因、出处 |

"需要确认"一列只数还没人看过的。"明细"表新增"原值""人工审核""审核原因"三列。
时间换成电脑所在时区再写入（数据库存 UTC，Excel 不支持带时区的时间）。

**接口：**
- `GET /documents/{id}/export.xlsx`：一个文档；
- `GET /documents/export.xlsx?ids=…&ids=…`：多个文档进同一个 Excel，按传入顺序、去掉重复，一次最多 100 个。

用 GET 而不是 POST，浏览器里一个链接就能下载。只有 done 和 reviewed 的文档能导出，否则 409 并列出文件名；
找不到的 id 返回 404。

**下载文件名：** 一个文档用原文件名（`收据.jpg` → `收据.xlsx`），多个用 `jacara-日期-N份.xlsx`。
中文文件名按 RFC 6266 写在 `filename*=UTF-8''…` 里，另带一个英文的 `filename` 给老程序。

## 后果

- 导出在 API 请求里同步完成：几十个文档、几秒钟，不需要放进后台队列。将来要导出上千个时再改成后台任务。
- `/documents/export.xlsx` 必须写在 `/documents/{document_id}` 前面，否则 FastAPI 会把 `export.xlsx` 当成文档 id。

## 放弃的方案

- **导出器直接查数据库**：违反规则 7，导出器也就没法在命令行和测试里单独用了。
- **给"审核之后的值"另做一个导出器**：两份几乎一样的代码；用 `reviews` 是否为空区分就够了。
- **POST 一个 id 列表再返回文件**：浏览器链接没法直接下载，前端要多写一段代码。
