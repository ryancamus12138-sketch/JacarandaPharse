# 0040 模型给两样：理解后的值和原文的写法

状态：已采纳（2026-11），取代 ADR 0039 里"日期范围照抄原文、代码拆"和 ADR 0034 里按值的各种写法找出处的做法

## 背景

以前模型只回答一个值（2014-08-03、4.11），系统把它还原成各种写法（August 3, 2014、03/08/2014、$4.11……）
去原文里找出处。每遇到一种新写法就要补一条规则；漏了就被当成"原文里对不上"不填。
例如原文 "August 3 , 2014" 逗号前多一个空格，就没对上。

## 决定

数字、日期、日期范围字段，模型回答三样：

- **value**：理解后的标准值。数字只有数字，日期 YYYY-MM-DD，日期范围 {start, end}；
  看不出年份或日月顺序的不猜，填 null。
- **text**：原文里这个值一字不差的写法（"$4.11"、"August 3 , 2014"、"July 1 - July 31 , 2014"）。
- **blocks**：用了哪几块。

文字字段不变（value 就是原文）。提示词 extract-v8、discover-v5。

系统核对（`plugins/aligners/blocks.py` 的 `_quoted`）：

1. **找原文**：按 text 在模型说的那几块里找（只比文字，不管格式）；那几块没有就在整页找，标黄说明。
   整页都找不到：模型抄错了或编的，走原来按值找的办法，再找不到就不填（看了原图的留着，ADR 0038）。
2. **交叉检查**（`plugins/aligners/crosscheck.py`）：用规则把 text 读一遍，看和 value 对不对得上：
   - 对得上：绿；
   - 对不上（原文 $4.11，模型给 4.0）：标黄，写明两边；少了小数点（原文 100、模型 1）写明可能是小数点没认出来；
   - 分不清（01/07/2014 又没选国家）：标黄让人确认；
   - 规则读不出这种写法：标黄"请看一眼"，**值照样留着**。新写法最多让人看一眼，不会再被丢掉。

存储：value 存标准值（日期范围存 "2014-07-01 ~ 2014-07-31"）；text 记在出处里（evidence.quote）。
审核页的日期范围显示"2014-07-01 ~ 2014-07-31"，下面"31 天 · 原文：July 1 - July 31 , 2014"；
导出选"原文"时用 quote（人改过值就用改过的）。

删掉了专门为找出处补的格式规则：日期被改写成 YYYY-MM-DD 的文字值（rewritten_dates）、
同一高度找少小数点的数字（_near）。这些情况现在由 text + 交叉检查覆盖。
留下的读数字、读日期、读日期范围、24 小时制时间的规则只用来：交叉检查、
人工改值和点原文填值时把写法换成标准值、模型没给 text 的老格式回答。

## 后果

- 回答长一点（每个数字、日期多一段原文），处理时间多约一成。
- 以前处理过的文档不受影响；重新处理才用新提示词。
- 日期范围的值从"原文"改成"标准值"，原文在出处里；拆开、公式、导出不变。
