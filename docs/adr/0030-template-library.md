# 0030：模板库、重新处理与用样例建模板（方案 B）

- 状态：已采纳
- 日期：2026-11-13

## 背景

v1 只有一个内置收据模板，字段写在 `templates/*.toml` 里，换一种单据就要改代码。
2026-11-12 决定按《JacarandaParse v2 模板方案（B）》在 v2 里做完模板功能：
用户自己的模板库、起步模板、重新处理、用样例建模板，参考 Rossum、Docparser、LlamaExtract、
Textract、Nanonets、Azure Document Intelligence 等产品的做法（方案第五、六节的四条经验）。

## 决定

### 1. 三种模板，一种格式

- **内置模板**（`templates/*.toml`：receipt、receipt_full）：评测和命令行用，保持原样，
  不做必填检查，结果和以前一样。网页上传不再选它们；没选模板、也没有上次记录时，按老办法用 receipt。
- **起步模板库**（`templates/starters/*.toml`，九个）：中国数电发票、航空运输电子客票行程单、铁路电子客票、
  通用发票、澳洲税务发票、通用收据、购物小票、餐厅小票、酒店账单。
  名字里带"通用"的（通用发票、通用收据）不带任何国家或地区的规定，只有所有同类单据都有的项目和
  不分地区都成立的金额关系；澳洲的要求（ABN、GST、ATO）放在澳洲税务发票，以及按用户要求参照 ATO 的
  购物小票、餐厅小票里（2026-11-12 决定，原来的"国际通用发票 / 澳洲税务发票"拆成两个）。
  字段按官方规定整理（税务总局公告 2024 年第 8、9、11 号，ATO 收据和税务发票要求，EN 16931，
  schema.org LodgingReservation），说明里只写通用规定，不放任何真实单据的内容。
- **我的模板**（新表 `templates`、`template_versions`）：从起步模板复制、复制我的另一个模板、空白新建、
  或者用样例建。定义是和 .toml 一样结构的 JSON，用同一个函数检查。

### 2. 版本：保存一次是一个新版本，旧文档不变

`template_versions` 只新增不修改。文档和抽取结果记下用的是哪个版本（`template_version_id`），
审核页的中文名、规则、导出的列都按那个版本还原；模板以后再改，已有的结果不变。
想按新版本重新抽，用"重新处理"。模板可以归档（不出现在上传的选择里，用过的文档照常显示）。

**导出、导入、删除**：`GET /templates/{id 或起步模板名}/export` 下载 JSON 文件
（`format = "jacarandaparse-template"`，内容和定义一样），`POST /templates/import` 导入成新的我的模板
（来源记 `import`，从第 1 版算起，检查和保存时一样）。`DELETE /templates/{id}` 删除模板和全部版本，
但有文档用过（任何一轮的抽取结果，或者正排队等着用）就拒绝（409），提示归档：删了那些文档就还原不出
字段中文名、规则和导出的列。删除记审计日志 `template:delete`。

### 3. 字段的新属性

- `aliases`：单据上的其他写法（Check-in、Arrival、入住日期），拼进给模型的说明。
- `export`：导出时要不要这一列；`sensitive`：敏感信息（证件号码），默认不导出。
- 字段 ID 存过之后不能改（规则、导出、旧文档都靠它对齐），中文名随便改。
- 必填：起步模板和我的模板里 `required` 的字段（或"至少一行"的表）没值，记一条"必填"错误，字段标红。
- 新规则（`rules.py` 的 `TEMPLATE_RULES`）：数电发票号码 20 位、合计金额 + 合计税额 = 价税合计、
  铁路电子客票 金额 + 税额 = 票价、行程单增值税 = (票价 + 燃油) ÷ (1 + 税率) × 税率、明细合计、大写金额 = 小写（先把大写解析成数字再比，不在乎圆/元、整/正的写法）、
  行程单金额合计、通用发票 净额 + 税 = 含税、应付不超过含税、ABN 校验位、
  1,000 澳元以上税务发票写了买方、ATO 收据五项、82.50 澳元以上要税务发票、GST 不超过 1/11、
  收据 小计 − 折扣 + 附加费 + 小费 + 调整 = 总额、离店在入住之后、晚数。规则按字段 ID 找值，
  所以起步模板里同一个意思的字段用同一个 ID（total、issue_date……）；缺字段的规则自动跳过。

### 4. 上传时选模板

上传多一个参数 `template`：我的模板的 id，或者 `discover`（不用模板，抽出所有键值对）。
不写就用这个人上一次用的。网页在上传框上方选，记在浏览器里；还没有自己的模板时提示去模板库添加。

### 5. 重新处理：新的一轮，旧结果留着

- `POST /documents/{id}/reprocess {template?, reason, note}`：原因必选（模板改了、选错了模板、
  结果不好、换了模型或 OCR、其他），"其他"要写说明；记审计日志 `document:reprocess`。
  不选模板就用现在这个模板的最新版。
- 每处理一次是一"轮"：`extractions.run`、`documents.current_run`。新一轮**处理成功**才换过去，
  失败了旧结果照常能用。`Document.extractions` 只有当前这一轮，`all_extractions` 是全部。
  审核页可以切换查看旧的几轮（只读，后端也拒绝改旧轮的值）。所有统计、筛选只算当前这一轮。
- **沿用上次的审核**：同一个字段 ID、出处框差不多在同一个位置，而且这次的值 = 上次审核后的值（建议"确认"），
  或者这次的值 = 上次模型抽错被人改掉的那个值（建议"改成上次人改的值"）。审核页显示紫色标签，
  "采纳上次的确认"一次用上，每个字段记一条审核记录（原因写明沿用第几轮）。其他情况要人重新看。

### 6. 用样例建模板

1. 上传时选"抽取所有键值对"：提示词 discover-v1，模型列出单据上所有"名称：值"，
   存成 `kv.1`、`kv.2`……，单据上的原名存在 `extracted_values.label`。没有规则。导出时这类单据单独一张"键值对"表。
2. 审核页"存成模板"：勾选要的、起中文名和字段 ID、选类型和必填，还可以加单据上没有的字段。
3. `POST /templates/from-sample`：新建模板第 1 版（原名记成别名），样例文档直接换成按新模板的新一轮：
   选中的值连同出处、人工改过的记录原样搬过去，**不重新调用模型**；自己加的字段是空的。

### 7. 试跑

`POST /templates/{id}/trial {document_id}`：用最新版在一份处理过的文档上抽一次（用存下的 OCR 结果，
不重新识别文字），返回每个字段的值和出处、规则结果，**不保存**。同步等模型，最多 3 页。

### 8. 导出

汇总表、表格表的列名用模板里的中文名，顺序按模板；`export = false` 的字段、表、列不写（明细表里也不写）。

### 9. 权限

新权限 `template:manage`（管理模板：新建、保存、归档、试跑、用样例建模板），管理员可以开通给使用者。
看模板只要能看文档。

### 10. 顺手的两件小事

- 网页按页面分开打包（打开哪个页面才下载哪个），第一次打开下载的东西少很多。
- `jacara start` 启动 llama-server 时关掉它自带的聊天网页（`--no-webui`），并每次生成一个密钥：
  通过环境变量 `LLAMA_API_KEY` 交给模型服务（不写在命令行上），worker 继承 `MODEL_API_KEY`，
  命令行从 `.run/model-key`（只有自己能读）读。本机别的程序不知道密钥就用不了模型。
  自己单独 `jacara serve` 启动的模型没有密钥，照常能用。

## 不做

- 不在系统里加任何评测功能，也不给模板标"未评测"（2026-11-12 决定）。评测由用户最后单独安排。
- 财政电子票据（医疗、行政事业收费）的票面要素没找到可核实的官方全文，没有做起步模板。
- 用样例建模板只收键值对；表格在模板编辑器里加。
