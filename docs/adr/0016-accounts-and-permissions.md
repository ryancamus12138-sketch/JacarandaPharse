# 0016 账号、权限和审计日志

- 状态：已采纳
- 日期：2026-11-08

## 背景

到第十七课为止只有个人模式：不用登录，所有操作都算在 `PERSONAL_OWNER` 头上，`require()` 直接通过。
几个人一起用时，需要知道"现在是谁"、限制谁能做什么，并且事后能查"谁在什么时候做了什么"（项目规则 3、5）。
个人模式要继续能用，不能因为加了账号就必须登录。

## 决策

**两种模式。** `.env` 里 `JACARA_MODE=personal`（默认）保持原样；`team` 模式必须登录。
切换只改配置，业务代码不变：所有接口本来就通过 `Depends(get_owner)` 拿当前用户，
service 本来就调用 `require()`（第十四课起），这次只改了 `get_owner()` 和 `require()` 两处。

**角色：管理员 + 使用者，权限按人勾选开通。** 起初设计了查看者 / 审核员 / 管理员三个固定角色，
但实际使用中"能上传但不能改字段"这类组合很常见，固定角色表达不了。改成：

| | 权限 |
| --- | --- |
| 使用者都有（`BASE`） | 看列表和详情、下载原图、导出、看修改历史 |
| 管理员按人开通（`GRANTABLE`） | 上传文件、重新处理、修改和确认字段、完成审核 |
| 只有管理员（`ADMIN_ONLY`） | 管理用户、查看审计日志 |

只有管理员能开通权限。`ADMIN_ONLY` 不在可开通的范围内，接口只接受 `GRANTABLE` 里的名字（否则 422），
`allowed()` 计算时也只认 `GRANTABLE`，所以使用者无论如何拿不到管理权限，没有"互相开权限再升级"的路。
权限存在 `users.permissions`（JSON 列表），每个请求现查，开通或取消马上生效，不用重新登录。

**密码：Argon2id（argon2-cffi，MIT）。** 只存哈希，自带随机盐。用户名不存在时也拿一个假哈希验证一次，
响应时间一样，猜不出哪些用户名存在；登录失败统一回答"用户名或密码不对"。密码至少 8 个字符。

**登录 token：随机串 + 数据库会话，不用 JWT。** `secrets.token_urlsafe(32)` 生成，只返回一次；
数据库 `auth_sessions` 只存 SHA-256，带过期时间（`SESSION_HOURS`，默认 12 小时）和作废时间。
每个请求查一次会话：退出、停用用户、重设密码都立刻生效。JWT 发出去就收不回来，而一次查询对本地工具不是问题；
因此也不再需要签名密钥（`.env` 里去掉了 `JACARA_SECRET_KEY`）。
请求头用标准的 `Authorization: Bearer <token>`（FastAPI 的 `HTTPBearer`，/docs 有 Authorize 按钮）。

**用户只停用，不删除。** 修改记录、审计日志里引用着 `user_id`。停用后不能登录，已有会话立刻作废。
管理员不能改自己的角色、不能停用自己，避免团队里没人能管理。

**团队：现在一个安装一个团队。** 第一个团队沿用个人模式的 team id（`…0001`），
从个人模式切到团队模式后，以前的文档都还在。表结构已经按多团队设计（所有查询按 team 过滤），以后需要时再加多团队管理。

**第一个管理员用命令行建：** `jacara user add admin --role admin`。密码用 `getpass` 输入，不显示、不进终端历史。
能在这台电脑上运行命令的人可以 `jacara user password` 重设任何人的密码。

**审计日志 `audit_logs`：只追加。** repository 只有 add 和查询。记录登录（含失败）、退出、上传、重新处理、
修改或确认字段、完成审核、导出、新建或修改用户、命令行建用户和重设密码。只看不改的操作不记。
日志和业务数据在同一个事务里；登录失败要抛错，所以先提交再抛，失败记录才能留下。
用户名存在时，失败记录记在那个账号下，管理员能看到"有人在试这个账号的密码"。只有管理员能查看。

**403 统一处理。** `require()` 抛 `PermissionDenied`，`app.py` 的异常处理器统一变成 403，
提示写明缺什么权限、该找谁（"请找管理员开通" / "只有管理员能做"）。401 表示不知道你是谁，403 表示知道但不允许。

## 后果

- 测试默认个人模式（conftest 的 `personal_mode`），不受开发者自己 `.env` 的影响；`test_auth.py` 自己切到团队模式。
- Argon2 每次几十毫秒，测试多了几秒。
- 前端（下一阶段）用 `/auth/me` 的 `mode` 决定是否显示登录页，用 `permissions` 决定显示哪些按钮。
  token 在 /docs 刷新后会丢，前端要自己保存。
- 没有做：登录失败次数限制、改密码接口、多团队管理、单点登录。都在本地离线场景里优先级低，需要时再加。

## 放弃的方案

- **三个固定角色（查看者、审核员、管理员）**：组合不够灵活，见上。
- **审核员也能开通权限**：审核员之间可以互相开权限，等于没有限制。
- **JWT**：收不回来，见上。
- **删除用户**：历史记录会失去"是谁"。
- **把权限写进 token**：改了权限要等 token 过期或重新登录才生效。
