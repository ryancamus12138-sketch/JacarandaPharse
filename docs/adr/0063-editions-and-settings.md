# 0063 个人版和团队版、设置页

状态：已采纳（2026-11）

## 个人版和团队版：一份代码，用 `JACARA_MODE` 区分

- **不分两份代码。** GitLab 以前社区版、企业版各一个仓库，一次安全修复要在两边提约 150 个合并请求，
  2019 年合成了一份代码（GitLab 博客"A single codebase for GitLab Community and Enterprise Edition"）。
  本项目团队版的代码不多、许可也一样（Apache 2.0），不像 GitLab 那样要把付费部分单独放进 `ee/` 文件夹，
  所以连单独的文件夹也不要：同一份代码，运行时按 `JACARA_MODE` 区分。
- **个人版**（`JACARA_MODE=personal`，默认，安装包用这个）：不用登录、所有权限都有（ADR 0021 的个人模式），
  只监听本机。界面上不显示团队才有的东西：退出、用户管理、审计日志、"团队和权限"。
- **团队版**（`JACARA_MODE=team`）：登录、管理员 / 使用者、开通权限、审计日志页。代码全部保留，测试照跑
  （`test_auth.py` 等在团队模式下跑），以后要放到局域网给几个人用时再补：HTTPS、登录失败锁定、API 密钥
  （规则 11 要求只监听本机，局域网访问要另写 ADR）。
- **权限检查不删。** 个人模式下 `require()` 总是通过，但每个操作照样调用（规则 5），审计日志照样记，
  个人版的人也能在"设置 → 关于和诊断"之外用命令行查到；以后切到团队版不用补。
- 前端只看 `/auth/me` 的 `mode` 决定显示什么，不在别处判断。

## 设置页

"系统信息"改成"设置"，分几类（参照 Immich：每个人自己的"账号设置"和管理员的"系统设置"分开，
系统设置按类别一页一页放）：

| 一类 | 内容 | 谁能改 |
|---|---|---|
| 个人 | 昵称、头像、密码（团队版） | 自己 |
| 识别和处理 | 看原图、PDF 怎么读、OCR 长边、版面分析、从人改过的地方学、自动收集纠错样本、后台分两个工位、监视文件夹、上传大小、接口文档页 | 管理员 |
| 模型 | 换模型（ADR 0046；模型库 ADR 0059 里的版本也在这里选，模型库页不再有"用这个版本"） | 管理员 |
| 数据和备份 | 数据量、怎么备份和恢复（ADR 0054） | 大家能看 |
| 团队和权限 | 用户管理、审计日志（只有团队版） | 管理员 |
| 关于和诊断 | 版本、各项服务通不通；模型服务地址、模型文件名这些细节只给管理员看 | 大家能看 |

模板不在这里显示（"模板"页有）。

进了设置以后，左边栏整个换成设置的这几类，最上面一个"返回"，回到进设置之前的那一页（记在浏览器这个标签页的
sessionStorage 里，没有就回工作台）；网址是 `/settings/类别`。

## 页面上改的设置存在哪、谁优先

- 存在 `data/settings.json`（本机的，不进仓库；和 `models/selected.json` 一样，备份不含它）。
- **`.env` 优先**：`.env` 或环境变量里写了的，页面上显示"由 .env 指定"、改不了。参照 Immich：
  指定了配置文件（`IMMICH_CONFIG_FILE`）以后，网页上就不能再改那些设置。
- 实现用 pydantic-settings 的设置来源顺序：初始化参数 → 环境变量 → `.env` → 页面设置 → 默认值。
  页面设置只读白名单里的这几项，文件里写了别的（例如数据库密码）也不认。
- 后台 worker 启动时读一次配置，所以改完要 `jacara stop`、`jacara start`；页面上保存后提示"要重启"，
  和换模型一样。
- 只有管理员能改（`system:manage`），记审计日志（`settings:update`，记改了哪几项、改成什么）。
