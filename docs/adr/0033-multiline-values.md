# 0033：折行的值（商品名、地址写成两行）

- 状态：已采纳
- 日期：2026-11-12

## 背景

用户反馈：商品名、地址折成两行时，只认出第一行；商品名折行时还会被拆成两行商品。
另外，有文字层的 PDF 按整行给文字（排版用空格对齐），出处框会从店名一直框到同一行右边的日期和房间数。

原因：给模型的文字按"视觉行"编号，提示词要求每个值只填一个行号；PDF 文字层用
pdfplumber 的 `keep_blank_chars=True` 合并，空格多的 PDF 一整行变成一块。

## 决定

分三步：按位置找线索 → 模型决定 → 证据对齐核对。

1. **按位置找"可能接着上一行"的行**（`plugins/ocr/layout.py` 的 `continues`）。同时满足才算：
   上下空隙不超过字高 × 0.8；字高相差不超过 1.45 倍；第一块和上一行某一块左边对齐（差不到 1.5 个字高）；
   第一块是文字（不是金额、数量）；不是"名称："开头。给模型的文字里这种行的行号后面加 `↳`。
   这只是线索：标题下面紧挨着的值、店名下面的地址，位置上也像"接着写的"，是不是同一个值由模型判断。
2. **提示词 extract-v5 / discover-v2**：每个值多一个 `row_end`。值跨几行时按原文顺序连起来
   （中间一个空格），`row` 填第一行、`row_end` 填最后一行；只取属于这个字段的部分（店名不带地址）；
   表格里商品名折行仍是同一行商品。`row_end` 比 `row` 小或不是正整数时当作没给。
3. **模型还是拆开了的兜底**：表格里某一"行"只有文字列有值、数字列全空，并且就在上一行商品的下一行、
   位置上是接着写的（有 `↳`），就并进上一行商品。小节标题（"饮料"）在商品上面、不是接着写的，不会被并进去。
4. **证据对齐**：模型说的几行（`row`～`row_end`）优先找；跨几行拼起来比较时，每行只留和这个值有关的文字块，
   否则第一行后面的数量、金额会夹在两段名字中间。出处框是这几块合起来的一个框。行号差错的提示也按这个范围算。
5. **PDF 文字层按词之间的空隙分块**：先取单个词，同一行里空隙不超过字高 × 0.6 的连成一段，
   再宽就分开（另一列）；冒号结尾的词（"Guest Name:"）后面也分开，后面是值。
6. **出处框只框值**（用户 2026-11-12 拿 OYO 账单试出来的两个问题）：
   - 店名 "OYO 4189 Resort" 的框一直拉到同一行最右边的房间数 "1"：挑"值的一部分"时，"1" 是 "4189" 的子串也被挑上了。
     现在不到 3 个字的文字块，只有和值完全一样才算。
   - 值只是一块文字的一部分（"Date: 31/12/2017"、"Guest Name: Sanjay"、"Rs 1939"）时，按字在块里的位置
     沿块的上下边按比例截出值那一段。只改框，出处的文字还是整块原文（负号、"原文值"要看整块）。

7. **列标题和值上下对齐的排版**（`header_groups`、`layout_hints`）：上面一行是几个标题（每块有字、没有数字，至少 2 块），
   下一行紧挨着（空隙不超过字高 × 1.5），至少 2 块按左边对齐或中心落在标题范围里，分别对到不同的标题，
   而且六成以上的块对得上；再往下"接着上一行写"的行，对得上哪一栏就接到哪一栏。
   找到后在 OCR 文字后面加一段"版面提示"：`第 12 行是列标题，下面按列对应：Hotel Details = "…"（第 13～14 行）；Rooms = "1"（第 13 行）`。
   变成一行行文字以后，"1 在 Rooms 下面"这层关系就没了，模型只能猜；有了提示，模型才知道这是房间数、不是晚数。
8. **起步模板"酒店账单"第 2 版**：酒店名称照抄完整写法（连分店名、地区）、加别名 Hotel Details；
   晚数、房号写明"Rooms 一栏是房间数"；房号去掉容易混淆的别名 Room；补 Check In、Booking ID、Payment Mode 等别名。
   已经"添加到我的模板"的副本不会自动变，要重新添加或手动改。

## 影响

- 提示词版本从 extract-v4 变成 extract-v5：以前的评测数字是 v4 的，换成 v5 后要重新跑一次评测才能比较（由用户安排）。
- 有文字层的 PDF 分块变细，行的划分不变（同一行的块还是合成一个视觉行）。
- 旧数据不受影响：存下来的值和出处不变，重新处理时才按新办法。

## 没做的

- 有表格线时按格子划分（表格结构识别）在 v3 第 3 批做，那时同一格里的几行直接就是同一个值。
