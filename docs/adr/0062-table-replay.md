# 0062 回放比较表格明细

状态：已采纳（2026-11）。去掉 ADR 0053 回放"只比单个字段"的限制。

## 为什么

商品明细这类表格，人审核时会删行、加行、改格子，抽出来的行和审核后的行顺序、行数都可能不同，
不能按行号直接比。

## 参照

DocILE 基准的明细识别（Line Item Recognition，LIR）评测（Šimsa 等，ICDAR 2023，arXiv:2302.05658，第 4.2 节）：
先对每一对（标准答案的行，预测的行）逐格评估，再在标准答案的行和预测的行之间找最大匹配，使总召回最高；
主指标是所有明细格子上的 micro F1。

## 做法

- 标准答案：审核后的"当前结果"（`pipeline/current.py`：跳过删掉的行、人加的行在里面、按显示顺序）。
  按公式算的列不比（和单个字段一样）。
- A 是"当时存下的结果"时，取模型当时抽的格子（包括后来被人删掉的行；人加的行模型没给过）。
- 配对：一对行的分数 = 这一对里对了的格子数（比较规则和单个字段一样：数字按数值，文字去掉多余空白），
  用 `scipy.optimize.linear_sum_assignment(maximize=True)` 找总分最大的配法。一格也没对上的配对不算配上：
  那一行人审核后的格子算"漏"，抽出来的格子算"多"（和算成"错"相比 P、R、F1 不变，但更好读）。
- 每一边：对 / 错 / 漏 / 多，micro 精确率 = 对 /（对 + 错 + 多），召回率 = 对 /（对 + 错 + 漏），F1。
- 两边对比：人审核后的每一格在两边的对错（两边各自配对），修好、弄坏、精确 McNemar、按业务单据分组的 bootstrap，
  和单个字段一样；多出来的格子和行另外报。
- 结果：`summary.md` 多一节"表格明细"，`summary.json` 多 `tables`，每一格写进 `cells.jsonl`（业务数据，只在本机）。

## 依赖

新增 scipy（BSD-3）。
