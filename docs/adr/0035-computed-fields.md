# 0035：计算字段和自己写的规则

- 状态：已采纳
- 日期：2026-11-12

## 背景

酒店账单的"晚数"交给模型去单据上找，模型抓了 Rooms 下面的 1（房间数）。这张单据碰巧也是 1 晚，
值对了、出处错了；换一张住两晚的单据就会填错。字段说明里写"Rooms 是房间数，不是晚数"也拦不住。

晚数本来就不该"找"：它等于离店日期 − 入住日期。同类的还有明细的金额 = 数量 × 单价、总额 = 明细合计。
v3 第 3 批原本就计划做"计算字段 / 自定义规则"，这次先把计算字段的核心做出来。

## 决定

**模板字段可以写公式（`compute`）。** 有公式的字段不交给模型，处理时在核对出处之后按公式算出来。

公式能写的东西是固定的，用 Python 的语法树逐个节点检查，不执行任意代码：

- 字段 ID、数字、`+ - * /`、括号；两个日期相减得到相差几天
- 表格每一行的公式里直接写同一行的列名（`quantity * unit_price`）
- `sum(items.amount)`、`count(items)`、`round(x)`、`round(x, 2)`、`abs`、`min`、`max`
- 文字字段不能参与计算；结果是数字，字段类型要是 number
- 模板保存时检查：名字不存在、类型不对、互相引用，都说清楚是哪个字段的公式、错在哪

**算的时候用核对过的值。** 原文里核对不上、按规则没有填的值（rejected，ADR 0034）当作没有；
缺值时这个字段是空的，说明里写"「入住日期」没有值，算不出来"。

**存成普通字段，origin = computed，status = computed。** 没有出处框（不是从原文找的），
说明里写公式和结果（"按公式算：离店日期 − 入住日期 = 1"）。证据这一维算"一致"：
对不对看参与计算的字段和规则。

**审核时跟着重算。** 参与计算的字段改了、表格增删了行，按公式再算一次，值变了就记一条
`action = "compute"` 的审核记录（谁改的那个值，记在谁名下）。这不算"人审核过"。
人直接改过的计算字段（最后一条是 edit）不再跟着变：人改的值说了算。处理时和审核时用同一份代码
（`pipeline/compute.py`），两边算出的值一定一样。

**起步模板"酒店账单"升到第 3 版：晚数 = `check_out - check_in`。** 已经复制到"我的模板"的不会自动改：
模板记着它是从哪个起步模板复制的（source = starter:hotel_folio），编辑器里提示"起步模板后来加了公式"，
点"套用"填进去，再保存成新版本。

**自己写的规则。** 模板可以加、删自己的规则（`custom_rules`），条件用同一套公式写成"左边 比较 右边"：
`sum(items.amount) == total`、`check_out > check_in`、`total <= 5000`；选"每一行"时每行单独检查，
条件里写那张表的列名。比较两边要都是数字或都是日期，数字相等允许差半分钱（和内置规则一样）。
缺值时跳过，不算错。不通过时说清楚两边各是多少：「明细的金额合计 是 9，总额 是 10，不满足 明细的金额合计 = 总额」。
编号按顺序是 custom_1、custom_2……，和选的内置规则一起检查。

**模板有地区。** 起步模板写 `region`：中国数电发票、铁路电子客票、航空行程单是 cn，澳洲税务发票是 au，
其他都是通用（空）。通用模板只能选通用规则，地区模板只能选通用规则和本地区的规则，保存时检查，
选错了说清楚是哪几条。购物小票、餐厅小票原来带着澳洲 ATO 的规则和说法（商家 ABN、GST、82.50 澳元），
第 2 版改成通用的：商家税号、税额，规则只留通用的。加地区之前复制的模板，地区跟它的起步模板一样。

**写公式不用记字段 ID。** 公式和规则条件的输入框右边有个按钮，列出这个模板现在有哪些字段
（中文名和字段 ID，只列数字和日期）、表格合计、比较符号和函数，点一下插到光标处；
边写边检查（`POST /templates/formula-check`，用编辑区现在的字段，不保存），
下面一行用中文显示意思（"= 离店日期 − 入住日期"），写错了说哪里错。

**编辑器只列通用规则。** 内置规则分通用和地区（cn：中国发票、行程单；au：澳洲 ATO、GST、ABN）。
编辑器只列这个模板用得上（要的字段都有）的通用规则（地区模板再加本地区的），加上这个模板已经选了的；地区规则和缺字段的规则不列，
别的检查自己写。地区规则留在后端，只给中国发票、澳洲税务发票这些地区起步模板用
（ABN 校验位、大写金额这类检查写不成公式）；从它们复制的模板照常显示、可以关掉。

## 没有选的做法

- **让模型算**：小模型做日期运算不可靠，而且结果没有出处可核对。
- **只用规则检查（stay_nights）**：只能发现不一致，填不出正确的值；模型抓错了出处，规则也看不出来。
  规则保留：人手动改了晚数时还会检查。
- **用 eval 或表达式库**：eval 不安全；表达式库要多一个依赖，而需要的运算很少。

## 后果

- 起步模板的计算字段不再出现在给模型的提示词里，提示词短一点。
- 从 Excel 导入模板（ADR 0031）暂时不认公式，导入后在编辑器里填。
- 后面的"自定义规则"（第 3 批）可以复用同一套公式检查和计算。
