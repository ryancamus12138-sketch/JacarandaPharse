# 0053 每轮的记录、回放、错误归因、补收样本

状态：已采纳（2026-11）。依据外部评审意见（B1、B4、A2 和"记录发给模型的文字块"）。

## 为什么

要回答"换了模型 / 提示词以后是不是真的更好""这个错是 OCR 的还是模型的"，需要三样东西：
当时 OCR 认出来的原样、当时发给模型的是什么、人审核过的值。以前只存了后两样的一部分，
OCR 结果按单据切开、坐标换过（给审核页用），不能原样再喂给流水线。

## 1. 每一轮的 OCR 快照

- 每处理完一轮，把 OCR 认出来的每一页原样（四个角、置信度、引擎和模型、PDF 文字层、表单字段）
  存进对象存储 `ocr-snapshots/<文档>/run-<轮>.json`，格式和流水线两个工位之间交接的 JSON 一样（ADR 0051）。
  一个进程做完和两个工位做完都存。
- `extractions.ocr_snapshot` 记着这一轮的快照在哪里，同一轮的几张单据指向同一个文件。
- 存不进去只记日志，不影响处理结果。删除文档时一起删。
- 这次更新之前处理的没有快照；回放时可以加 `--reread` 重新认字（结果里注明，差别里混着 OCR 的变化）。

## 2. 记下发给模型的是什么

- `extractions.model_input`：版面原样里写进去的文字块编号、一共几块、单据文字原文和 sha256、
  附了几张原图、带了几个以前改过的例子。
- 审核页抽取说明那一行显示"发给模型 N 个文字块"，点开看原文（`GET /documents/{id}/extractions/{eid}/sent`）。
  值不在这里面是 OCR 没认出来；在里面却没取到是模型漏了。

## 3. 回放（B4 最小版）：`jacara eval replay`

- 只回放审核完成的单据，人审核过的值当标准答案。
- A 默认是"当时存下的结果"（不重新跑），B 是要试的模型服务；两边也可以都重新跑、各自带或不带例子。
  两边用同一份 OCR 快照（结果里记了每份快照的 sha256）。模板用当时那一版（自动判断的按现在能选的）。
- 比较单个字段（表格明细这一版不比）：对、错、漏、多；修好了几个、弄坏了几个、新漏掉几个、标黄的变化。
- 统计：精确 McNemar（修好对弄坏）、按业务单据分组（ADR 0052 的组）bootstrap 准确率差的 95% 区间
  （固定种子，2000 次）；证据等级和样本导出一样（不到 10 组或 50 个字段只说明流程跑通）。
- `--split test_locked` 只回放锁定测试集。
- 只读：不改数据库里的任何东西。结果写到 `data/eval/replay/<时间>/`（summary.md、summary.json、
  fields.jsonl），data/ 不进 Git；fields.jsonl 有业务数据的原值，只放本机。
- 版本清单：jacara 版本、两边的设置、实际用的模型和提示词版本、模板版本、OCR 引擎和模型、划分版本。

## 4. 错误归因（B1）

人改过的字段（值和模型给的不一样），按证据判断错在哪一步，**证据不够就说"证据不够"**：

| 阶段 | 证据 |
| --- | --- |
| OCR 认错了字 | OCR 样本是"认错字"；人点的原文 OCR 读出来不是人填的值；人框的地方 OCR 读的不是人填的值 |
| OCR 没认出这块 | OCR 样本是"漏认"；人框的地方 OCR 一个字都没有 |
| 模型取错或漏取 | 人填的值就在发给模型的文字里（按字段类型比：数字按数值、日期两种顺序都认）；模型把日月读反 |
| 标准化或出处匹配 | 模型给的其实是对的，被出处核对丢掉了，或者只是写法不同 |
| 模板或规则 | 模板（按国家）定的日月顺序让日期读反了 |
| 几处都有问题 | 上面几步都有证据（例如这块 OCR 认错了，别处的文字里却有对的值） |
| 证据不够 | 值不在 OCR 文字里、又是手打的；值太短（一位数、一个字），找到也可能是碰巧 |

- 存在 `error_attributions`：阶段、原因代码、证据（样本 id、文字行和块号、OCR 读的文字……）、
  规则版本 `attr-v1`。统计页打开时补上还没判断的；又改过的、规则版本变了的重新判断。
- 人可以改判（统计页"最近的修改"里点阶段），改判的不会被重新判断覆盖，审计日志记一笔。
- 更新之前处理的单据没有 model_input，用存下的 OCR 文字代替（那时整页文字都发给模型），证据里注明。
- 统计页加"错在哪一步"汇总。敏感字段不给证据原文。

## 5. 从以前的修改补收 OCR 样本（A2）

- "OCR 样本"页"从以前的修改补收"：审核时点了原文或框了一块、改了值的修改，裁出小图，
  `origin=backfill`、状态"待复核"。手打的不收（不知道在图上哪里）；同一次修改只收一条；
  敏感字段、PDF 自带的文字不收（和 ADR 0050 一样）。
- 图中原文先猜一个（点一块原文的：OCR 读的；框的：框选重新识别读的），旁边写着当时字段改成了什么。
  人对着小图改对、点"通过"才变成可以导出；"不要"就撤回。导出预览把没复核的列为"补收的，还没复核"。
- 复核通过时按人确认的原文重新分类。错误归因只用复核过的样本。
