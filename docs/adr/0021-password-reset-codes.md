# 0021 改密码和忘记密码：一次性重设码

- 状态：已采纳
- 日期：2026-11-11

## 背景

最初只有管理员能改密码（命令行 `jacara user password`），用户管理页的第一版加了网页上的
"管理员重设密码"。问题是管理员会知道对方的新密码，密码不再只属于本人。

常见的做法是"忘记密码 → 手机短信或邮件验证码 → 自己设新密码"。但短信和邮件都要联网、
要第三方服务商，还要把手机号或邮箱交出去，违反规则 1（离线）；没网的内网环境也根本发不出去。

## 决策

**自己改密码。** 登录后右上角"修改密码"：先输原密码，新密码不能和原来的一样。
改完以后别的设备上的登录都退出，正在用的这个不退出（`revoke_sessions(keep=当前 token 的哈希)`）。

**忘记密码：一次性重设码。** 思路和短信验证码一样（先证明"你是你"，再自己设新密码），
只是码由管理员当面或电话交给本人，不经过任何外部服务。

- 管理员在"用户管理"点"重设码"，得到 8 个字的码，比如 `K7QM-3XWD`；
  字母表去掉了容易看错的 0 O 1 I，输入时不分大小写、不管横线和空格；
- 15 分钟有效，只能用一次；同一个人再生成一个，旧的作废；停用的用户不能生成；
- 新表 `password_reset_codes`，只存码的 SHA-256（和登录 token 一样），记下谁生成的；
- 本人在登录页"用重设码设新密码"：用户名 + 码 + 新密码。用户名或码不对时不说是哪个错了；
  成功后这个账号所有登录都退出；
- 审计日志记 `user:reset_code`、`auth:password_reset`、`auth:reset_failed`、`auth:password_change`，
  不记码，也不记密码。

**删掉"管理员直接设密码"的接口**（用户管理页第一版的 `POST /users/{id}/password`）。
命令行 `jacara user password` 保留：唯一的管理员也忘了密码时，能操作服务器的人还有办法。

**为什么 8 个字够。** 32 选 1，8 位约 1 万亿种。码 15 分钟过期，就算每秒猜 1000 次也只能试 90 万次，
猜中的概率不到百万分之一。登录 token 要长得多，是因为它能用 12 小时，而且不用人念出来。

## 后果

- 管理员和本人要能当面或电话联系上，才能把码交过去。对本地小团队不是问题。
- 没有做登录和重设的失败次数限制。以后如果要放到更大的网络里，再加。
- 以后真有能联网的部署想要短信或邮件，可以做成可选插件，默认关闭，不改这里的流程：
  只是把"管理员告诉本人"换成"系统发给本人"。

## 放弃的方案

- **短信或邮件验证码**：要联网和第三方服务，见背景。
- **管理员设临时密码，下次登录必须改**：管理员还是知道临时密码，在被改掉之前能用它登录。
- **管理员直接设密码**（第一版）：管理员知道新密码。
