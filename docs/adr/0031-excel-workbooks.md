# 0031：从 Excel 建模板、按原工作簿导出、多 sheet（对象、参照表）

- 状态：已采纳
- 日期：2026-11-12

## 背景

用户手上常有一张公司规定要交的 Excel（报销汇总、发票登记表、实验数据汇总），希望：
按这张表建模板，上传单据后直接导出成和它一模一样的 Excel。真实的 Excel 有标题行、两层表头、
下拉选项、合计行，还常常有好几张 sheet，各管各的（汇总 + 明细、按月分、病人信息 + 实验数据 + 实验室名单）。
另外，模板要能用一个人看得懂的 Excel 导出、修改、再导入，不只 JSON。

参考：CDISC SDTM（每张表写明"一行代表什么"，靠受试者编号相连）、REDCap（record_id 串起一个人的资料，
可重复的表单一次一行）、Sensible（单值字段一张表、表格各一张、多份文档追加行）。

## 决定

### 1. 通用方法：每张 sheet 一个角色

不管哪个行业，每张 sheet 回答五个问题：表头在哪一行、一行代表什么、用哪一列认出一行（编号）、
每一列从哪来、导出时怎么填。按答案归成五种角色：

| 角色 | 一行代表 | 变成模板里的 | 导出 |
|---|---|---|---|
| 单据表 document | 一份单据 | 普通字段 | 一份一行 |
| 明细表 items | 单据里的一项 | 表格（tables） | 一项一行，带单据上的字段 |
| 对象表 entity | 跨单据的一个人 / 公司 / 地点 | 对象（entities）：编号字段 + 属于它的字段 | 同一个编号合并成一行 |
| 参照表 reference | 一条固定资料 | 参照表（references）：整张表的数据 | 原样不动 |
| 选项 options / 不用 ignore | — | 下拉选项变成字段的可选值 | 原样不动 |

单 sheet、"汇总 + 明细"、按月分的几张，都是它的特例。

### 2. 分析（猜）+ 预览（人确认）

`workbook/analyze.py` 只猜：前 20 行里第一行"文字格够多、都不像数字日期"的是表头，上一行横向合并的格子
合成两层表头；表头下面到连着三行空行为止是数据，合计行不算；数据验证（下拉框）里的值是可选值，
被引用的 sheet 是选项；名字像"名单""字典""代码表"的是参照表；两张表有同名编号列、一边一个编号一行
另一边好几行，好几行的是明细表；一个编号一行而且表头像人或单位的是对象表；表头完全一样的几张记成 same_as。
列：序号、文件名这类是系统自动；报销人、部门、审批这类是人工填；和参照表同名的列，第一列拿来对照，其余从参照表填。
表头和起步模板对上 2 列以上，就用它的字段 ID、类型、说明，规则里字段都有的一起带过来。

预览页（`/templates/excel/{upload_id}`）每张 sheet 一张卡片，写着猜的角色和理由，每一列的来源、中文名、
字段 ID、类型、必填、敏感都能改。确认后 `workbook/build.py` 建模板：几张 sheet 里同一个字段 ID 就是同一个字段，
只抽一次。上传的 Excel 先存在 `template-uploads/`，建好后另存一份 `templates/files/`，记在模板的 `workbook.file`。

### 3. 模板里新加的

- 字段：`options`（可选值，写进给模型的说明；不在里面标黄，规则 `options`）、
  `extract`（false = 人工填：不交给模型，处理时放一个空值，origin 记 manual，审核时填）。
- `entities`、`references`、`workbook`（每张 sheet 的角色、表头行、每一列填什么：字段 ID、`items.amount`、
  `auto:seq`、`ref:名单.列名`、空）。
- 参照表对照（规则 `lookup`）：拿字段（或表格的列）的值到参照表的对照列里找，不分大小写、全角半角、空格；
  找不到标黄。最多 5000 行，存在模板定义里。
- 对象冲突（`pipeline/entities.py`，规则 `entity_conflict`）：审核页打开一份文档时，同一个模板、当前这一轮、
  同一个团队里同一个编号的其他单据，属于这个对象的字段写得不一样就标黄，说明是哪几份、各写的什么。最多比 50 份。
- 编辑器保存新版本时，对象、参照表、工作簿样式从上一版带过来；删掉的字段在这几处的引用自动去掉（导出时那一列留空），
  不报错。这几样在编辑器里只读，要改结构就重新从 Excel 建。

### 4. 按原工作簿导出（`workbook/fill.py`）

几份文档都用同一个模板的同一版、而且它有工作簿样式时，导出 Excel 就填回原表（取不到原文件就退回标准格式）：
表头下面原来的数据清掉，新数据用原来第一行数据的格式；原来有合计行的，在最后补一行合计（SUM 公式）。
明细表每一项一行，带着单据上的字段；对象表同一个编号合并成一行，几份写得不一样的格子标黄、批注里列出各份写的；
参照表、选项、说明不动。表头一样的几张 sheet（按月分的）：原来的都不动，复制第一张，填进复制出来的那张。
模板里设成不导出（包括敏感）的字段，那一列留空。

### 5. 标准模板 Excel（方法一，`workbook/standard.py`）

`GET /templates/{名字}/export?format=xlsx`（默认）导出：模板、字段、表格、规则、对象、参照表几张表，
外加每份参照名单一张"参照-名字"；类型和是/否的列带下拉框。上传时有「字段」表、表头有"中文名""字段ID"的
就按这个格式读，写错的地方说清楚哪张表第几行；字段 ID 可以不填（自动编号）。
按原表导出的样式不在标准 Excel 里，要搬用 `format=json`：JSON 里带着原 Excel（base64），导入时另存一份。

### 6. 接口

- `POST /templates/excel`（上传）：标准模板 Excel 返回 `kind=standard` 和读出的模板（再用 `/templates/import` 建）；
  业务报表返回 `kind=report`、`upload_id` 和每张 sheet 的猜测。
- `GET /templates/excel/{upload_id}`：再分析一次（刷新预览页）。
- `POST /templates/excel/{upload_id}/build`：按预览确认的结果建模板。

## 不做

- 只支持 .xlsx（老的 .xls 让用户另存为 .xlsx）。
- 不自动找"表头在第几行"以外的版式（例如表格横着放、一张 sheet 里上下好几块表）。
- 参照表不单独维护：要更新名单就重新从 Excel 建模板。
- 对象只能由单据上的普通字段组成（不能是表格的列）。

## 影响

- 不需要新的数据库迁移：新东西都在模板定义（JSON）里。
- 新目录 `backend/src/jacara/workbook/`；导出、审核页、校验器都多了上面几样。
