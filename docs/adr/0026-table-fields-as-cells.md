# 0026：表格字段（商品明细）的每一格当作一个普通字段

- 状态：已采纳
- 日期：2026-11-11

## 背景

收据和发票上有商品明细：行数不固定，每行有商品、数量、单价、金额。v1 只能抽单个字段。
商品明细同样要找出处、规则校验、人工审核、记修改历史、导出，而且审核、修改历史这一套已经按"一个字段一行"做好了。

## 决定

1. **模板里写表格**：`[[tables]]` 加 `[[tables.columns]]`，列的写法和普通字段一样（name、label、type、description）。
2. **大模型按表格回答**：JSON Schema 里每张表是一个列表，每行是 `{"row": 行号, 列名: 值}`，行数不设上限。
   提示词版本 extract-v4。整行都是空的不算一行；表格的列不能叫 row。
   第一版（extract-v3）每一格都写成 `{"value", "row"}`，商品多的收据回答超过 4096 个 token 被截断，
   而一行商品本来就在同一行，所以改成每行只写一次行号，回答短一半多。
3. **表格必须完整，不限制模型回答的长度**：不再传 `max_tokens`（`ModelConfig.max_tokens = None`），
   JSON Schema 保证模型写完 JSON 就停；llama-server 的上下文长度从 8192 调到 32768，能放下几百行商品；
   等待上限 600 秒。真被截断（超过上下文长度）时整张单据失败并说明原因，不会存一张缺了行的表。
4. **每一格存成一个普通字段**，名字是 `表名.第几行.列名`，例如 `items.2.amount`（第 2 行的金额，行号从 1 开始）。
   `extracted_values` 表不加列、不用迁移；找出处、审核、修改历史、导出、接口全都照旧。
   `cell_name()` / `split_cell_name()`（`plugins/extractors/base.py`，前端 `fields.ts` 的 `splitCell`）负责拼和拆。
5. **两条新规则**：
   - `items_sum`（警告）：商品金额加起来 = 小计（模板里有小计时）或总额。只标黄商品金额，不标总额。
     税、服务费、折扣常常单独列，所以只是警告。
   - `item_line`：每一行 数量 × 单价 = 金额，差 1 分钱以内算对；缺数量或单价的行跳过。
   规则增加两种写法：`needs` 里可以写 `items.*.amount`（所有行），`per_row="items"`（每行单独检查）；
   `flags` 指定不通过时标黄哪些字段。
6. **Excel 多一张"商品明细"表**：一行商品一行，前面是文件名和第几行，颜色和批注同"汇总"。
   "汇总"里不放格子；"明细"里每一格一行，方便筛选。
7. **审核页面**：普通字段下面画一张表；点一格 = 左边高亮出处，表格下面展开审核表单。

## 不做（以后再说）

- 审核时增加、删除一行：现在只能改格子的值。漏了一行要靠"商品金额合计"规则提醒。
- 商品明细的评测：SROIE 没有明细的标准答案。

## 影响

- 收据模板（receipt、receipt_full）升到第 3 版。旧文档没有商品明细，照常显示。
- 模型回答变长，每张收据处理时间会变长，评测时注意看用时。
- 风险：模型偶尔会陷入重复（一直写同一行），这时要写满上下文才停，一张单据可能要几分钟，最后失败。
  评测里出现就再处理（例如检测重复行），不靠限制行数解决。
- 插件接口只加不删：`Extractor.extract()` 加了可选的 `tables` 参数，`Rule` 加了可选的 `per_row`、`flags`。
