# 0054 备份和恢复

状态：已采纳（2026-11）。

## 为什么

用真单据审核出来的数据（审核记录、模板、OCR 样本、快照）重新做一遍代价很高。数据库和对象存储
分开备份会对不上（数据库说有这个文件、存储里没有），所以要一起备份、一起恢复，并且真的恢复一次才算数。

## 做法

- `jacara backup`：先确认 `jacara start` 没在运行（暂停写入），把数据库每张表和对象存储里每个文件
  打进一个 `backups/jacara-<时间>.tar`。PostgreSQL 在同一个快照（REPEATABLE READ）里读所有表。
  写到 `.partial`，写完、核对过才改名；文件权限 600。`backups/` 在 .gitignore 里。
- 包里：`manifest.json`（格式、时间、jacara 版本、数据库版本、每张表几行、每个文件的 sha256 和类型）、
  `db/<表>.jsonl`、`objects/<路径>`。
- 表结构从数据库读（SQLAlchemy reflect），不用 pg_dump：不依赖本机的 pg_dump 版本，
  测试里能完整跑一遍备份、恢复、核对。
- `jacara restore <包>`：只恢复到空的环境（每张表都没数据、存储里没有文件）。先核对整个包
  （每张表行数、每个文件 sha256），一处不对就什么都不动；把数据库结构变成备份时的版本，
  在一个事务里写完全部数据并核对行数，再放回文件，最后升级到最新版本。
- 恢复以后逐样打开：每个原始文件（PDF 用 pdfium 打开、图片完整解码）、每份文档的每一轮、
  每个字段和修改历史、每个模板版本、每张 OCR 样本小图、每份 OCR 快照、导出记录的文件、头像。
- `jacara restore-drill <包>`：恢复演练。用 `docker compose -p jacara-drill` 另起一套空的
  PostgreSQL 和 SeaweedFS（端口 55432、58333，单独的数据卷），恢复进去、逐样打开，
  默认做完删掉这套演练环境（`--keep` 留着）。平时用的数据库和存储完全不碰。

## 不做的

- 不做在线（不停机）备份：现在是单机、个人或小团队用，停一下再备份最简单可靠。
- 不做增量备份、定时备份：先保证"能完整恢复"；定时可以以后用系统的定时任务调 `jacara backup`。
- 不备份 Valkey（任务队列）：里面只有排队中的任务，恢复后在列表里重新处理即可。
