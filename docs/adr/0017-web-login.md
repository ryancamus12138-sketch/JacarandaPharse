# 0017 前端登录和路由

- 状态：已采纳
- 日期：2026-11-10

## 背景

后端第十八课有了团队模式和 token 登录。前端需要：登录页、记住登录、每个请求带 token、
token 失效时回到登录页，以及按权限显示菜单。个人模式不能出现登录页。

## 决策

**路由用 react-router（MIT）。** 网址和页面一一对应，能收藏、能刷新、能前进后退。
切换页面不重新加载整个网页。登录后的页面共用一个外框（`AppLayout`），中间用 `<Outlet />` 换页面。

**token 存在 localStorage。** 刷新和新标签页都不用重新登录。风险是网页里如果跑了坏脚本能读到它；
应对：网页只运行我们自己打包的代码（规则 1，不从 CDN 加载），token 12 小时过期，
停用和退出在后端立即生效（每个请求查会话表，见 ADR 0016）。
没有用 httpOnly cookie：那需要后端改成 cookie 认证并处理 CSRF，对本机工具收益不大。

**"现在是谁"打开网页时问一次。** `AuthProvider` 调 `/auth/me`，结果放进 React Context，
所有页面用 `useAuth()` 拿。200 = 已登录或个人模式；401 = 还没登录（正常情况，不算错误）；其他 = 后端有问题。

**401 统一处理。** `client.ts` 带着 token 收到 401，就清掉 token 并通知 `AuthProvider`，
守门员 `RequireAuth` 把人带到登录页，并记下原来的地址，登录后回去。没带 token 的 401（比如密码错）不触发。

**菜单和页面按权限显示，但只是为了好看。** `can('user:manage')` 决定显不显示；真正的权限检查在后端，
直接调接口照样 403。权限改了，前端刷新后菜单才变；后端每个请求现查，马上生效。

## 后果

- 新页面放进 `App.tsx` 的路由，管理员页面套 `RequirePermission`。
- 新接口在 `src/api/` 里加函数，页面不直接写 `fetch`。
- 部署时后端要把 `/documents` 这类网址都返回 `index.html`（单页应用），在部署那一课处理。
