# 0052 OCR 样本按单据分组、划分训练集和验证集

状态：已采纳（2026-11）。依据外部评审意见（A1），按原意见完整实现，不简化。

## 为什么

同一张单据的几行字，一部分进训练、一部分进验证，模型等于先看过答案，验证分数虚高。
同一张单据的 PDF 和照片、重新处理的几轮、重复上传的同一个文件，也都是"同一张"。

## 分组的单位：业务单据

- 一个业务单据 = 一个文件里的一张单据（`documents.id` + 这张单据的起始页）。重新处理的几轮、
  这张单据的每一页都属于它。文件 ID、抽取记录 ID 都不能直接当组：一个 PDF 里可以有好几张单据，
  每次重新处理会多一条抽取记录。
- 表 `doc_group_members`：业务单据 → `group_id`（随机 UUID，不含业务信息）。第一次有样本时分配。
- **字节完全一样的文件**（sha256 相同）同一起始页直接进同一组，不用确认。
- **PDF 和照片**（不同文件）：按 单据类型（模板）+ 单号（模板里"不能重复"的字段）+ 日期 + 金额 + 币种 + 发单方
  提名，两边都有的都要一样；模板没有单号字段时要 发单方、日期、金额 都有且一样才提名。只有日期和金额一样不提名。
  提名只是候选，**人并排看两张原图确认**后才合并；"不是同一张"也记下来（`doc_pair_decisions`），不再提名。
  也可以手动把两张单据配成一组，或把配错的拆开。

## 划分

- 每个团队一个随机种子和一个划分版本（`team_settings`：`ocr_split_seed`、`ocr_split_version`，从 1 开始）。
- 一组第一次进数据集时：`SHA-256(种子:版本:group_id)` 取 0～9999，前 2000 个桶进验证集，其余进训练集，
  结果写进 `split_assignments(版本, group_id, split)`。之后导出一律读表，不再重新算。
  80/20 是按组的目标比例：组少、一组样本多时行数比例会偏，界面照实显示组数和行数，不为凑比例挪动已有的组。
- `test_locked`（锁定测试集，管理员手动锁）：不进普通的训练/验证导出、不当"从人改过的地方学"的例子来源；
  单独导出。等有足够多新进、能独立标注的单据再建。
- `quarantined`（隔离）：见下。不进任何导出。

## 合并、拆开和隔离

- 合并两组：两边划分一样，照旧；不一样、而且**两边都还没被导出过**，并到保留那一组的划分；
  不一样、**有一边已经被导出过**，合并后的组隔离（可能已经一份训练、另一份验证），
  在受影响的导出记录上记一笔（哪一组、为什么、什么时候）。"只要某个模型已经用其中一份训练过，
  另一份就不能再用来独立评估该模型"——这条优先于"每次都落在同一边"。
- 拆开（配错了）：拆出来的单据换一个新组。原来的组已经被导出过的，两边都隔离。
- 隔离的组管理员可以手动处理：归训练集（不再用于验证）或锁成测试集。

## 导出

- `rec_gt_train.txt`、`rec_gt_val.txt`、`rec_gt.txt`（两者合起来），图片共用 `crop_img/`；
  `manifest.jsonl` 每条加 `split`、`split_version`、`sample_revision`（图中原文改一次加 1）、
  `document_group`（`g_` + 种子和 group_id 的哈希前 12 位：稳定、不含业务信息）。
- 锁定测试集单独导出（`rec_gt_test.txt`）。
- 每次导出记一条 `ocr_sample_exports`：划分版本、范围、每条样本的 ID、修订号、组、划分。
  同一份数据、同样的范围重复导出，成员一样。
- 预览和 README 照实写：训练、验证各几组、几行；验证集 **少于 10 组或少于 50 行** 标"只能检查流程"，
  **15 组以上、100 行以上** 才"可以看整体趋势"，中间"偏少"；按模板、分类、PDF/照片报分布，
  验证集里每种分类来自几组。不做多维分层（会破坏组边界）。交叉验证不放进导出。

## 验收

同一张单据重新处理几轮、PDF 和照片、同一个文件里几张单据、导出以后才发现重复（合并 → 隔离 → 记在导出记录上）；
同样的数据重复导出成员一致；训练和验证的组没有交集；锁定测试集不进普通导出、不当教训来源。
